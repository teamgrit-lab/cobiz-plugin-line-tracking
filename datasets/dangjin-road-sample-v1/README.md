# 당진 실제 센서 주행 샘플 v1

전면 영상과 LiDAR를 함께 검토할 수 있도록 만든 **검토용 샘플 데이터셋**입니다. **기록된 제어 명령은 없으며, `estimated_command`의 전진·회전·정지 값은 모두 추정 제안**입니다. 전문가가 승인한 이상적 행동의 정답이나 검증된 주행 정책으로 취급하지 마세요.

[영상·LiDAR·명령을 함께 보는 검토 화면](index.html)을 브라우저에서 열면 됩니다. `index.html`과 `review_data.js`, 구간별 폴더를 같은 위치에 유지하면 서버 없이 사용할 수 있습니다.

## 구성

| 구간 | 원본 MCAP 끝부분 | 요청한 추출 구간¹ | 표본 수 | 장면 |
|---|---|---:|---:|---|
| `straight` | `_1-009.mcap` | 기록 시작 +10~22초 | 24 | 축사 사이 직선 도로, 후반 좌측 방향 보정 |
| `right_turn` | `_7-027.mcap` | +9~21초 | 24 | 오른쪽으로 이어지는 길의 진입부 |
| `vehicle` | `_32-025.mcap` | +12~28초 | 31 | 교차로의 트럭, 적재물 가림, 횡단 차량 |

¹ 기록 시작 시각에 오프셋을 더해 선택한 40초 분량의 창입니다. 실제 촬영 시각은 각 행의 `camera.header_time_ns`입니다. 목표 추출률은 2 Hz이며, 영상 표본 사이의 1.1876초 공백 한 곳을 보간하지 않아 총 79개입니다. 우회전 전체나 우사 한 바퀴를 포함하는 데이터셋은 아닙니다.

- 전진 16개, 우회전/우측 보정 23개, 좌회전/좌측 보정 3개, 정지 37개.
- 정지 중 31개는 차량 및 가림 상황에서 양보하는 정책 제안입니다. 나머지 6개는 단일 LiDAR 스캔의 지면 근거 부족으로 판단을 보류한 것으로, **장애물 때문에 반드시 정지해야 한다는 정답이 아닙니다**. `stop_reason`과 `training.exclusion_reasons`로 구분합니다.
- 전면 영상: 1280×720 원본 해상도 PNG 79장. 360도 영상이 아닙니다.
- LiDAR: 각 영상에 대응하는 실제 스캔 79개. 원본 센서 좌표 XYZ, 점별 촬영 시각, 유효점 마스크를 NPZ에 보존했습니다. 반사 강도·tag·line 등 원본의 모든 필드를 복제한 형식은 아닙니다. 전체 메시지는 MCAP에 남아 있습니다.
- 연속 문맥 확인용 영상 3개. 640×360, 명목 10 fps입니다. 누락 프레임을 채우지 않은 고정 프레임률 미리보기이므로 **재생 시각으로 센서를 동기화하지 마세요**. 각 구간의 `video_index.json`에 실제 촬영 시각을 기록했습니다.

## 관측과 추정의 구분

| 항목 | 위치 | 의미 |
|---|---|---|
| 원본 관측 | `raw_samples.jsonl`, `images/`, `lidar/` | 기록에서 추출한 영상, XYZ, IMU, 시각, 메시지 해시 |
| 실제 기록 명령 | `recorded_command` | 모든 행에서 `null`. `/cmd_vel` 등 제어 명령 토픽이 없음 |
| 실제 이동 속도 | `observed_motion` | `null`. IMU를 주행 명령으로 바꾸거나 불일치 GPS 속도를 사용하지 않음 |
| 영상 주석 | `annotations.json`, `visual_annotation` | 도로 중앙 방향의 대략적인 경로와 차량 박스. Codex 시각 검토 및 촬영 시각 기준 보간; 사람 검수 전 |
| 지면·거리 | `geometry` | LiDAR 국소 평면, 경로 주변 근거. 아래의 미확인 외부 보정 가정에 의존 |
| 제안 명령 | `estimated_command` | 바람직한 동작의 후보. `is_estimated: true`; 실제 운전자 명령/학습된 모델 출력/최적 해가 아님 |

차량 박스 안으로 투영된 LiDAR 점의 거리 통계는 **물체 고유 거리의 정답이 아닙니다**. 다른 전경·배경 반환점이 포함될 수 있고, 점이 부족하면 `null`입니다. 가림 전후 트럭이 같은 차량인지도 `unknown`으로 남겼습니다.

## 명령 생성 방법과 가정

1. 모든 추출 영상을 연락판으로 검토하고 일부 핵심 프레임을 원본 해상도로 확인했습니다. 키프레임의 대략적인 도로 중앙 경로를 영상 좌표로 제안하고 중간 프레임은 촬영 시각 기준 선형 보간했습니다. 정밀한 차도 영역 마스크는 아닙니다.
2. 기록된 카메라 K/D와 로컬 `livox-a2-front` 보정 프로필로 영상의 세 번째 경로 점을 LiDAR 지면에 교차시켜 로봇 기준 시선 목표 `(x,y)`를 추정했습니다. 지면은 강건 평면 추정(RANSAC)으로 계산합니다.
3. 저속 기준 전진 속도를 직선 0.25 m/s, 굽은 길 0.18 m/s로 설정했습니다. 이는 **설계 가정**이며 원본의 실제 속도, 로봇 한계 또는 검증된 최적 속도가 아닙니다.
4. 회전율은 `omega = v * 2*y/(x*x+y*y)`로 계산하고 ±0.18 rad/s 범위로 제한했습니다. 명령 좌표는 `base`: +x 전진, +y 좌측, +z 위쪽, **+회전율 좌회전 / −회전율 우회전**입니다. 횡이동 명령은 0입니다. 목표 방향이 ±5° 이내면 전진, 그 밖은 회전으로 분류합니다.
5. 영상의 차량 양보 주석, 센서 연결 품질, 경로 주변 지면 근거와 가까운 비지면 반환점을 참고해 정지 후보를 만들었습니다. 지면 후보 점이 충분한 0.5m 구간 비율이 60% 미만이면 판단 보류 정지입니다. 로봇 폭·여유 폭과 1.5m 장애물 기준 역시 가정입니다. 완전한 충돌 검사나 동역학 검증을 수행한 정책이 아닙니다.

모든 숫자 명령의 신뢰도는 `low`이며 보정된 확률이 아닙니다. 제안 시간 범위는 0.5초로 설정했으나 실제 구동 지연은 알 수 없습니다. 실제 로봇이 이 후보 명령을 실행한 결과 영상도 없습니다. 따라서 연속된 명령을 재생하면 기록 영상과 같은 궤적이 나온다고 해석할 수 없습니다.

## 시각·보정에서 확인한 제한

- 카메라는 헤더 촬영 시각, LiDAR는 **점별 촬영 시각의 최소·최대 중앙값**으로 가장 가까운 스캔을 연결했습니다. 전체 79개의 중앙 시각 차이는 최대 46.23ms로 연결 기준 60ms 안입니다. 하드웨어 동기화가 검증되었다는 뜻은 아닙니다.
- LiDAR 점별 `timestamp`는 float64 절대 Unix 나노초입니다. LiDAR 헤더는 스캔 시작, bag log는 수신 시각이므로 서로 구분했습니다. 약 100ms 스캔 중 로봇 움직임을 보정하는 deskew는 하지 않았습니다.
- GPS 속도 48개 대응 표본의 헤더 시각은 log 시각과 약 1,032초 불일치합니다. 진단 정보만 남겼으며 명령 생성과 시간 정렬 학습에 쓰지 않았습니다. 차량 구간에는 해당 GPS 메시지가 없습니다.
- 원본 CameraInfo의 K/D는 보존했습니다. 그러나 선택한 파일에 TF가 없어서 현재 로컬 프로필의 센서 장착 변환이 이번 촬영과 같은지는 확인되지 않았습니다. `calibration_assumptions.json`의 `verified_for_these_recordings`는 `false`입니다. 투영을 육안 확인했어도 캘리브레이션 검증을 대신하지 않습니다.
- 카메라의 검은 모서리와 장착물이 시야 일부를 가립니다. LiDAR에 점이 없는 공간은 자유 공간으로 판정하지 않습니다.
- 원본 파일은 읽기만 했습니다. 원본 경로·크기·수정 시각·토픽 목록과 선택 메시지의 SHA-256을 보존했습니다. `SHA256SUMS`는 **생성된 데이터셋 파일**의 해시이며, 2GB 원본 MCAP 전체를 해시한 것은 아닙니다.

## 학습에 쓰기 전

현재 모든 행은 `split: review_only`, `approved_for_training: false`, `human_verified: false`입니다. 이것은 별도의 작업 승인 요청이 아니라 데이터의 검수 상태입니다.

- 영상·투영·명령을 검토하고 센서 장착 보정과 구동 지연을 확인한 뒤 승인된 라벨을 별도 버전으로 만드세요. 지면 근거 부족 6개의 정지는 특히 재검토가 필요합니다. 이러한 보류 표본을 곧바로 “도로에서 정지”하는 전문가 행동으로 학습시키지 마세요.
- 연속 프레임을 무작위로 학습/평가에 나누면 유사 장면이 섞입니다. `training.group_id`는 원본 MCAP 파일명입니다. 같은 기록 세션의 다른 파일도 중복 경로가 있을 수 있으므로, 본격 평가에는 별도 날짜·주행의 기록을 확보하세요. 세 구간은 일반화 성능을 검증하기에 충분하지 않습니다.
- 주석 작성에는 전체 구간과 뒤쪽 키프레임도 참고했습니다. `offline_context_used: true`로 표시했으며, 현재 프레임만 사용한 실시간 모델 결과로 평가하지 마세요. 추정 명령과 인식 모델의 입력에 미래 프레임이 유입되지 않도록 학습 시 구성해야 합니다.
- **입력은 전면 카메라 1개입니다.** 전면 영상만으로 학습한 모델을 360도 전방위 인식 모델로 취급할 수 없습니다. 기존 브라우저 시뮬레이터의 다중 시점 입력 모델에 바로 넣지 마세요. 전면 모델을 구성하거나 360도 데이터를 추가해야 합니다. LiDAR는 여기서 teacher 근거이며, 최종 모델의 입력 여부는 별도 설계 사항입니다.
- 향후 실제 `/cmd_vel` 또는 로봇 제어 요청, 실행 속도·자세, 운전자 개입, 동기화한 영상·LiDAR를 함께 기록하면 모방 학습과 제안 명령 검증을 위한 근거가 좋아집니다.

## 파일과 재현

- `labels.jsonl`: 관측 참조, 영상 주석, 지면 근거, 제안 명령을 포함한 79행.
- `annotations.json`: 편집 가능한 키프레임 주석과 차량 양보 구간.
- `teacher_policy.json`: 명령 생성 정책과 가정값.
- `quality_report.json`: 시간 차이, 누락 구간, 명령 분포, GPS 진단.
- `validation_report.json`: 파일·배열·시각·부호·추정 구분의 자동 검사 결과. 명령의 전문가 정확도 검사는 아님.
- `straight/`, `right_turn/`, `vehicle/`: 원본 PNG, NPZ, 검토용 투영/조감도, 문맥 영상, 카메라 보정 정보.

프로젝트 루트에서 실행합니다. 추출에는 외장 볼륨과 기존 `.venv`의 `mcap`, `mcap_ros2`, NumPy, OpenCV, Pillow 및 ffmpeg가 필요합니다. 라벨 생성에는 SciPy도 사용합니다. 원본 경로는 `sources.json`에 있습니다.

```bash
.venv/bin/python tools/build_road_sample_dataset.py \
  --source '/Volumes/MY_HDD/무제 폴더' \
  --output datasets/dangjin-road-sample-v1
.venv/bin/python tools/label_road_sample_dataset.py \
  --dataset datasets/dangjin-road-sample-v1
.venv/bin/python -m pytest -q test/test_road_sample_dataset.py
.venv/bin/python tools/validate_road_sample_dataset.py \
  --dataset datasets/dangjin-road-sample-v1 --write-manifest
```

추출을 다시 실행하면 같은 출력 경로의 생성 파일을 갱신하므로, 사람 검수한 버전은 먼저 별도 폴더에 보존하세요. 라벨링만 수정할 때에는 MCAP을 다시 읽을 필요 없이 `annotations.json` 수정 후 두 번째 명령부터 실행하면 됩니다.
